# 算法核心接口说明（高新杰）

> 对应分工：快排递归主体 + 两种分区 + 三种基准 + 四种数据分布
> 本模块只产出“数据 + 过程”，不写界面；界面层把 `steps` 逐条播放即可。

## 一、文件清单

| 文件 | 作用 | 谁用 |
| --- | --- | --- |
| `core/quicksort.py` | 快排主体、两种分区、基准策略、步骤流、递归树、计数 | 界面层调用 |
| `core/data_gen.py` | 四种数据分布生成 | 界面“生成数据”按钮 |
| `core/benchmark.py` | 策略 × 分区 × 分布 对比实验，输出 Markdown/CSV | 技术文档的统计对比表 |
| `core/demo.py` | 命令行自测（打印步骤、递归树、ASCII 柱状图） | 开发自查、演示前核对 |
| `tests/test_core.py` | 18 组单元测试（正确性 / 步骤流 / 递归树 / 生成器） | QA 复用 |

## 二、三行接入

```python
from core import trace_sort, generate

data = generate("random", 16, seed=20261116)      # 生成数据
qs = trace_sort(data, pivot="median3", partition="hoare", seed=7)
qs.arr          # 排序结果
qs.steps        # 步骤流：一条一条播放
qs.comparisons, qs.swaps, qs.elapsed_ms
```

只要结果不要过程时用 `quick_sort(data, pivot, partition, seed)`，返回排好序的 list，不改动入参。

## 三、参数取值

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `pivot` | `"first"` | 首元素基准 |
| | `"last"` | 尾元素基准（首元素的对称变体） |
| | `"random"` | 随机基准 |
| | `"median3"` | 三数取中基准（low / mid / high 三者取中） |
| `partition` | `"lomuto"` | 单指针分区：基准移到末尾，`store` 划分“小于区” |
| | `"hoare"` | 双指针分区：基准放左端当哨兵，i/j 相向扫描互换，最后基准归位 |
| `distribution` | `"random"` / `"sorted"` / `"reversed"` / `"nearly"` | 随机 / 顺序 / 逆序 / 近乎有序 |
| `seed` | 整数或 `None` | 给定后“随机基准”“随机分布”可完全复现 |

> 课程要求“三种基准”，代码里给了四种：`first`/`random`/`median3` 正好是教材上的三种，`last` 是附赠的对称变体，界面下拉框可以只放三种。

两种分区的返回语义已经统一：**`arr[k]` 就是基准，左段 `[low, k-1]` 都不大于它，右段 `[k+1, high]` 都不小于它**。所以界面画递归树、做“基准归位”高亮时不用区分方案。

## 四、`steps` 步骤流

每一步都是一个 dict，公共字段：

| 字段 | 含义 |
| --- | --- |
| `type` | 步骤类型，见下表 |
| `message` | 中文日志文案，可直接写进日志面板 |
| `comparisons` / `swaps` | 执行到这一步时的累计比较 / 交换次数 |
| `array` | 此时刻的数组快照（`list`，已拷贝）；重绘柱状图直接用它 |

按类型划分的具体字段：

| `type` | 出现时机 | 附加字段 |
| --- | --- | --- |
| `start` | 开始排序 | `n`, `pivot_label`, `scheme_label` |
| `range` | 进入一个递归区间 | `low`, `high`, `size`, `depth`, `node` |
| `pivot` | 选定基准 | `index`, `value`, `strategy`, `low`, `high`, `depth`, `node` |
| `compare` | 与基准比较一次 | `i`（被比较下标）, `vi`（该元素值）, `pv`（基准值）, `pivot`（基准下标）, `op`（`"<"`/`">"`）, `rel`, `low`, `high`, `depth`, `node` |
| `swap` | 交换一次 | `i`, `j`, `a`, `b`（交换前的两个值）, `reason`, `pivot`, `low`, `high`, `depth`, `node` |
| `place` | 基准归位 | `index`（= `k`）, `value`, `low`, `high`, `depth`, `node` |
| `done` | 单元素区间直接就位 | `index`, `value`, `low`, `high`, `depth`, `node` |
| `end` | 排序结束 | `c`（比较总数）, `s`（交换总数）, `t`（耗时 ms） |

界面需要的三类“染色信息”都能拿到：

- **当前比较的两个柱子**：`compare` 的 `i` 与 `pivot`
- **当前交换的两个柱子**：`swap` 的 `i` 与 `j`
- **已经排好的柱子**：累计 `place` 和 `done` 里的 `index`，并集就是全部已就位下标（实测覆盖 0..n-1 无遗漏，有单元测试保证）
- **当前处理区间**：`range`/`compare` 等的 `low`、`high`，可把区间外的柱子画成灰色

## 五、`nodes` 递归树

每个元素对应一次划分，`nodes[0]` 是根：

| 字段 | 含义 |
| --- | --- |
| `id` | 节点编号（= 在 `nodes` 里的下标） |
| `parent` / `side` | 父节点编号、自己在父节点的哪一侧（`"left"` / `"right"` / `"root"`） |
| `low` / `high` / `size` | 该节点处理的区间与元素个数 |
| `depth` | 递归深度（根为 0） |
| `pivot_index` / `pivot_value` | 基准落在哪个下标、基准值 |
| `left_child` / `right_child` | 左右子节点编号，空区间不建节点，所以可能是 `None` |
| `comparisons` / `swaps` | 这一次划分自己用掉的比较 / 交换次数 |
| `done` | 是否已完成划分 |

递归树面板直接按 `depth` 分层、按 `parent`+`side` 连线即可；节点宽高可以按 `size` 做视觉权重。各节点 `comparisons`/`swaps` 之和恰好等于总次数（有测试保证），可以在节点上标注“本层比较 13 次”。

## 六、统计口径（写文档时要对齐）

- **比较次数**：只统计“元素与基准值”的比较，包括判定失败的最后一次；`median3` 挑基准时的三次样本比较**不计入**，也不产生步骤。
- **交换次数**：只统计真正发生了的元素交换；`i == j` 的无效交换不计数、不记录。
- **耗时**：`elapsed_ms` 已扣除“拼日志字符串、拷贝快照”的开销，只反映排序本身；界面显示“耗时”直接用这个值。
- **空数组 / 单元素**：比较、交换均为 0，步骤只有 `start`（+`done`）+`end`。

## 七、对接 `ui_layout.py`：`StepDriver`（推荐）

肖廣桂在 `feat/ui-render` 分支的 `ui_layout.py` 里留了三个对外接口：`set_sort_state(...)`、`add_tree_node(l, pivot, r, parent_id)`、`finish_sort()`。`core/ui_bridge.py` 的 `StepDriver` 已经把步骤流翻译成这些调用（方法签名已用 AST 逐项核对，一致），界面不需要自己解析步骤字段。

```python
from core import StepDriver, generate

self.driver = StepDriver(self)            # self 就是 QuickSortVisual 实例

# 1) 生成数据：算好步骤流，并推第一帧把柱子画出来
def generate_arr(self):
    ...                                    # 原有取长度、校验逻辑不动
    data = generate("random", n, seed=None)
    self.driver.load(data, pivot="median3", partition="lomuto")
    self.reset_all(keep_arr=True)          # 先清空旧的高亮/递归树/日志
    self.driver.step()                     # 推 start 帧 → 画柱子

# 2) 单步 / 自动播放：界面里那个占位方法直接接上
def step_sort(self):
    if not self.driver.step():
        self.log("已经播到最后一步")

# 3) 回看：进度条拖动
self.driver.seek(50)

# 4) 重置：保留步骤流，只回到开头
self.driver.reset()
```

适配层替界面做的事：

| 步骤 | 推给界面的调用 |
| --- | --- |
| `compare` | `set_sort_state(arr, compare=i, swap=-1, pivot=基准下标, ...)` |
| `swap` | `set_sort_state(arr, compare=j, swap=i, ...)` —— 界面只有一个"交换"高亮位，另一个端点借"比较"位一起标色 |
| `pivot` | `set_sort_state(arr, pivot=index, compare=-1, swap=-1, ...)` |
| `place` / `done` | 把该下标加入 `sorted_set`，同时 `add_tree_node(low, k, high, parent)` 画递归树 |
| `end` | `sorted_set` 补全 + `finish_sort()` |

两个细节：
1. **计数面板**：适配层会把 `step["comparisons"] / step["swaps"]` 写进界面的 `compare_cnt / swap_cnt` 并调用 `update_stat()`，所以顶部"比较次数 / 交换次数"会实时跳动（界面对象没有这些属性时会自动跳过）。
2. **递归树**：只在"基准归位"（`place`）时建节点，单元素区间不建，避免递归树塞满叶子；深度优先的步骤顺序保证父节点先于子节点创建，连线不会断。
3. **`finish_sort()` 里有 `messagebox.showinfo`**：连续演示时会弹模态框挡住动画循环，建议界面侧改成日志提示（这只是 UI 自己的改动，我没有动他们的文件）。

## 八、自己渲染时的最小示例

```python
import tkinter as tk
from core import trace_sort, generate

BAR_W, GAP, BASE_Y, SCALE = 24, 6, 380, 1.5   # 柱宽、间距、基线下沿、高度系数

class Demo:
    def __init__(self, root):
        self.root = root
        self.canvas = tk.Canvas(root, width=780, height=400, bg="white")
        self.canvas.pack()
        self.qs = None
        self.pos = 0          # 当前播放到第几步
        self.delay = 300      # 自动播放间隔（ms），速度滑块直接改它
        self.playing = False
        self.gen()

    # 生成数据：换分布/长度时重新来一遍
    def gen(self, n=16, dist="random"):
        self.qs = trace_sort(generate(dist, n, seed=20261116),
                             pivot="median3", partition="lomuto", seed=7)
        self.pos = 0
        self.render(self.qs.steps[0])

    # 按一条步骤重绘
    def render(self, step):
        self.canvas.delete("all")
        arr = step["array"]
        peak = max(arr) if arr else 1
        done = self.done_indexes(step)
        for idx, value in enumerate(arr):
            x0 = 20 + idx * (BAR_W + GAP)
            y0 = BASE_Y - value * SCALE
            color = "#66a3e0"
            if idx in done:
                color = "#4caf50"                       # 已就位
            if step["type"] in ("compare", "swap") and idx in (step.get("i"), step.get("j")):
                color = "#ff9800"                       # 正在比较/交换
            if idx == step.get("pivot"):
                color = "#e53935"                       # 基准
            self.canvas.create_rectangle(x0, y0, x0 + BAR_W, BASE_Y, fill=color, outline="")
            self.canvas.create_text(x0 + BAR_W / 2, BASE_Y + 14, text=str(value))
        self.root.title(f"比较 {step['comparisons']}  交换 {step['swaps']}")

    def done_indexes(self, step):
        # 累积到当前步为止所有已就位下标；正式实现里缓存成集合，避免每帧重扫
        return {s["index"] for s in self.qs.steps[: self.pos + 1] if s["type"] in ("place", "done")}

    def step_once(self):
        if self.pos < len(self.qs.steps) - 1:
            self.pos += 1
            self.render(self.qs.steps[self.pos])

    def play(self):
        if self.playing:
            return
        self.playing = True
        self._tick()

    def _tick(self):
        if not self.playing:
            return
        if self.pos >= len(self.qs.steps) - 1:
            self.playing = False
            return
        self.step_once()
        self.root.after(self.delay, self._tick)

    def pause(self):
        self.playing = False
```

要点：
1. 排序在 `trace_sort` 里一次性算完，播放只是“翻步骤”，所以暂停、调速、拖进度条都不影响结果——不需要后台线程。
2. 速度滑块回调里改 `self.delay` 即可，正在跑的 `after` 下一帧立刻生效。
3. “重置”= 用同一组 `seed` 重新 `trace_sort`，保证演示可复现；想看别的数据就换 `seed`。
4. 想支持进度条回看，用 `qs.array_at(i)` 直接取第 i 步的数组。

## 九、自测与实测结论

`python -m unittest discover -s tests -t . -v` → 28 项全部通过（0.07 s）：算法核心 18 项 + 适配层 10 项。

覆盖范围：4 种基准 × 2 种分区 × 4 种分布 × 8 种规模（0/1/2/3/5/16/40/100）；重复值、全等值、逆序、单逆序对等边界用例；步骤流回放一致性、元素守恒、已就位下标全覆盖、递归树父子链接与计数汇总。
另外做了 2000 轮随机对拍（16000 组参数组合，含 n=300、含重复值），失败数 0；n=1200 有序 / 逆序 + 首元素基准（最坏退化路径）也全部正确。

`python -m core.benchmark --sizes 200 500 1000 --repeat 3` 产出的完整数据在 `docs/基准策略对比数据.md`（另有同名 CSV）。关键结论：

| 场景（n=500，Lomuto） | 比较次数 | 耗时 |
| --- | --- | --- |
| 随机数据 + 首元素基准 | 4 426 | 1.60 ms |
| 顺序数据 + 首元素基准 | 124 750 | 21.68 ms |
| 顺序数据 + 三数取中 | 3 498 | 1.05 ms |
| 顺序数据 + 随机基准 | 4 413 | 1.32 ms |
| 近乎有序 + 首元素基准 | 119 970 | 20.72 ms |
| 近乎有序 + 三数取中 | 3 508 | 1.06 ms |

n=1000 时同一组对照是 499 500 次 / 85.69 ms 对 7 987 次 / 2.37 ms —— 固定基准在有序数据上退化到 O(n²)，三数取中把它拉回 O(n log n)，正好是演示里最值得讲的一组对比。

**一个需要如实报告的现象**：逆序数据 + 三数取中时，Hoare 分区的比较次数明显高于预期（n=500 为 32 123 次，n=1000 为 126 748 次，接近 O(n²)），而同样数据下 Lomuto 只有 6 018 / 14 378 次。原因是第一轮划分后左段会变成“首元素偏大、其余升序”的形态，此时 `(low, mid, high)` 三个采样点的中值恰好是区间里的次大值，于是每一轮都只能剥掉一个元素。这是三数取中在特定形态上的固有弱点，不是分区写错（结果始终有序，测试全绿）。可选的改进方向：
1. 采样点改为 `(low, mid, high)` + 随机点，或用 Sedgewick 的 ninther（九点取中）应对大数组；
2. 逆序数据先做一次“首尾互换”预处理再排序；
3. 保留现状，在技术文档里作为“基准策略也有失效场景”的分析案例——这一点对答辩反而是加分项。
